# GUI 设计规范（Desktop Application UI Guidelines）

适用于：所有桌面 GUI 代码（qs_robot_desktop*.py、UI 相关模块）

## 1. 基本架构规范

### 1.1 布局原则
- 顶部工具栏：关键操作按钮（刷新、优化、启动、停止）
- 左侧/中部：策略列表（Treeview，支持双击查看详情）
- 右侧/底部：结果面板（最佳参数、评分、模式分析报告、回测曲线）
- 状态栏：实时显示当前状态（绿色=正常、黄色=执行中、红色=失败）

### 1.2 线程安全
- ❌ 严禁在主线程执行耗时操作（优化、回测、网络请求）
- ✅ 必须使用子线程（threading.Thread）执行耗时操作
- ✅ 线程完成后通过 `root.after(0, callback)` 回到主线程更新 UI

```python
# 正确示例
def run_optimization_ui(self):
    """UI 入口：只负责启动线程，不做耗时操作"""
    self._set_status(f"优化中: {strategy}...", "orange")

    def run_thread():
        """子线程：执行实际优化"""
        result = self.strategy_mgr.run_tau_cluster_optimization(strategy)
        # 回到主线程更新 UI
        self.root.after(0, lambda: self._update_ui_after_opt(result))

    threading.Thread(target=run_thread, daemon=True).start()
```

## 2. 策略列表显示规范

### 2.1 列定义
- **名称**：策略名称（首列，可排序）
- **分类**：策略类型（趋势/套利/均值回归/轮动等）
- **优化状态**：必须显示 `v<版本号> | <评分>`，如 `v3 | 1.85`
- **运行状态**：运行中/停止（根据 strategy_mgr 状态自动刷新）

### 2.2 自动刷新机制
- 优化完成后，**必须**调用 `self._refresh_strategies()` 刷新列表
- 回测完成后，**必须**同步更新对应策略行的评分显示
- 策略启动/停止后，**必须**立即刷新运行状态列

### 2.3 Toolbar 按钮
- 🔄 **刷新列表**：调用 `_refresh_strategies()`，从参数存储读取最新状态
- 🔬 **韬定律优化**：对选中策略执行韬定律优化（自动识别策略类型）
- 🔬 **批量优化**：对所有策略依次执行韬定律优化
- 🚀 **启动策略**：应用最新优化参数后启动（调用 `strategy_mgr.start_strategy()`）
- 📈 **回测**：对选中策略执行回测（自动加载最新优化参数）

## 3. 优化结果显示规范

### 3.1 必须显示的内容
- ✅ 最佳参数（JSON 格式，缩进 2，可复制）
- ✅ 最佳评分（保留 4 位小数）、收益、总评估次数、缓存命中率、耗时
- ✅ 模式分析报告（坏参数模式/范围收缩建议/参数锁定建议/改进方向）
- ❌ 禁止把原始日志直接显示给用户（仅显示摘要，详细日志输出到文件）

### 3.2 优化中状态
- 状态栏必须显示"优化中: <策略名>..."（橙色）
- 按钮在执行期间应禁用或显示"进行中"
- 可通过日志面板查看实时进度

## 4. 回测与启动策略规范

### 4.1 回测默认行为
- **默认**加载最新优化参数（`use_optimized_params=True`）
- 回测结果必须显示：收益、夏普、最大回撤、胜率、交易次数

### 4.2 启动策略默认行为
- **默认**加载最新优化参数（调用 `strategy_mgr.apply_optimized_params()` 或直接传参）
- 启动成功后在状态栏显示"✅ 已启动（v<版本号>, score=<评分>）"
- 启动失败显示"❌ 失败：<错误信息>"（红色）

## 5. 错误处理与用户反馈

### 5.1 必须处理的边界情况
- 未选中策略就点击按钮 → 弹提示框："请先选中一个策略"
- 策略管理器不可用 → 弹提示框："策略管理器尚未初始化"
- 策略无优化记录 → 在状态列显示"未优化"（而非空白或报错）
- 参数存储加载失败 → 降级使用默认参数，并在状态栏提示

### 5.2 消息框使用原则
- `messagebox.showinfo()` —— 成功/提示
- `messagebox.showwarning()` —— 用户操作错误（如未选中）
- `messagebox.showerror()` —— 系统级错误（如策略管理器不可用）

### 5.3 日志输出
- 所有异常必须记录到日志面板（若有）或文件
- 日志格式：`[时间] [级别] 消息`
- 优化完成的成功日志应包含策略名、评分、耗时三项关键信息

## 6. 可扩展性规范

### 6.1 新增策略
- 无需修改 GUI 代码：策略注册到 strategy_mgr 后，刷新列表即可显示
- 自动识别策略类型并选择合适的优化器

### 6.2 新增优化器
- 必须同时实现：`run_<name>_optimization()` 方法 + 在 `_run_tau_for_strategy_blocking()` 中注册识别逻辑
- 优化完成后**必须**调用 `apply_optimized_params()` + `_refresh_strategies()`

## 7. 禁止事项

❌ 禁止在主线程调用任何耗时超过 1 秒的操作  
❌ 禁止修改策略的默认参数值（只能通过优化流程更新）  
❌ 禁止不刷新策略列表就结束优化流程（优化结果对用户不可见）  
❌ 禁止硬编码策略名称的下拉列表（必须从 strategy_mgr 动态读取）  
❌ 禁止在 GUI 中直接访问底层存储（必须通过 strategy_mgr / integration_bus）
