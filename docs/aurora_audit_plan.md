# Aurora 量化交易系统 内核+外壳 全维度审核方案

> **审核总纲**：以人体身心完整运行状态为评审标尺，核心目标——强化系统觉知能力与极速响应能力。

---

## 一、审核总纲：拟人化映射表

| 人体身心维度 | 对应 Aurora 系统模块 | 审核核心目标（觉知 + 快速反应） |
|:---|:---|:---|
| **气血通达** | 数据流转链路、服务通信、内存/IO/网络吞吐、多端口API适配器(5002/5003)、Mongo时序库、因子计算引擎Qlib | 数据流无阻塞、无瓶颈、无积压，信号从行情接收→因子运算→下单指令全链路低延迟流转 |
| **神经敏锐** | 事件监听、行情推送钩子、异常探针、风控实时传感器(risk_control.py)、MCP插件事件总线、盈亏滑点实时采集 | 毫秒级捕捉行情异动、参数漂移、接口报错、资金异动、策略偏离，不漏微弱风险信号 |
| **灵活灵透** | 多策略调度集群(strategy_registry)、熵韬收敛优化器(tau_optimizer_cluster)、GA遗传算法迭代、多模型切换、实盘/模拟环境隔离、参数动态调参 | 支持策略热切换、自适应市场、动态增减算力、快速适配不同周期标的，无僵化硬编码限制 |
| **思维敏捷** | 因子计算、收益/方差/熵评估、威科夫逻辑推理(wyckoff_factors)、AI信号判别(agent_dispatcher)、仓位演算、订单路径决策 | 模型与策略推理无卡顿，多因子并行运算极速输出交易判断，多情景推演瞬时完成 |
| **肌体健全** | 系统底层架构、服务集群(5002/5003)、硬件算力适配、灾备容错、日志/监控底座(system_health)、权限隔离(session/auth)、容器部署 | 无单点故障、模块无残缺、硬件资源匹配、崩溃自动恢复、完整运维兜底能力 |
| **意识清晰** | 状态可视化看板(dashboard/main_system)、全链路日志溯源、指标分层展示、错误告警分级(system_health_checker)、策略运行状态快照 | 任何时刻可直观看清系统每一层运行状态，故障定位零模糊，数据口径统一无歧义 |
| **全知全觉** | 全链路埋点、全维度监控(monitor/)、行情/资金/仓位/风控/算力/接口/模型全维度采集、离线复盘溯源 | 不存在信息盲区，历史+实时数据全覆盖，隐藏损耗、隐性风险全部可观测、可审计 |

## 三、阶段1：内核底层审核

### 3.1 气血通达 — 数据流专项

#### 审核项 QX-001：全链路延迟分段统计

**目标**：行情接收→因子运算→下单指令全链路P99延迟≤500ms。

**测试步骤**：
1. 启动行情源（Sina/AKShare），订阅 000001.SZ 实时行情
2. 在 `multi_data_source.py` 的 `get_historical()` 入口打点 T0
3. 在 Qlib 因子引擎 `qlib_adapter.py` 计算完成打点 T1
4. 在熵韬优化器 `tau_optimizer_cluster.py` 输出信号打点 T2
5. 在下单API `broker_interface.py` 生成指令打点 T3
6. 连续采集1000次，统计 P50/P95/P99 延迟

**验收标准**：
- P99 ≤ 500ms ✓
- 无单次超时 > 2s ✗

**测试脚本**：`tests/audit/test_latency_chain.py`

---

#### 审核项 QX-002：5002↔5003代理通信延迟

**目标**：反向代理请求延迟 P99 ≤ 200ms，无断流。

**测试步骤**：
1. 调用 `aurora_core_adapter.py` 的 `_proxy_get('/api/strategy/list')` 100次
2. 统计响应时间分布
3. 模拟 5002 服务重启，验证重试机制（3次退避）
4. 检查 `_proxy_session` 连接池复用是否生效

**验收标准**：
- P99 ≤ 200ms ✓
- 重试成功率 ≥ 95% ✓
- 连接池复用生效（同一Session对象） ✓

**测试脚本**：`tests/audit/test_proxy_latency.py`

---

#### 审核项 QX-003：数据库写入阻塞检测

**目标**：MongoDB 写入不阻塞主流程，单次 ≤ 50ms。

**测试步骤**：
1. 启用 MongoDB 慢查询日志（阈值 50ms）
2. 批量写入 1000 条 K 线数据
3. 并发 10 策略同时写入回测结果
4. 检查慢查询日志

**验收标准**：
- 零慢查询（>50ms） ✓
- 写入成功率 100% ✓

---

#### 审核项 QX-004：内存泄漏巡检

**目标**：运行 24 小时内存增长 ≤ 5%，无泄漏。

**测试步骤**：
1. 启动系统，记录初始内存占用
2. 持续运行回测+优化任务 24 小时
3. 每小时采样内存占用
4. 重点检查 `_rate_cache`（限流器）、`_strategy_map_cache`（策略缓存）

**验收标准**：
- 24h 内存增长 ≤ 5% ✓
- 无持续增长趋势（抛物线） ✓

| 系统层 | CPU/内存/磁盘/网络、进程状态 | 待审计 |

**测试步骤**：
1. 运行完整交易流程（行情→因子→策略→优化→下单）
2. 检查每个节点是否有日志/监控数据输出
3. 统计覆盖率

**验收标准**：
- 覆盖率 = 100% ✓
- 每个节点至少包含：时间戳、模块名、关键数据 ✓

**验收标准**：

#### 审核项 QZ-003：隐性损耗可观测

**目标**：延迟损耗、算力浪费、接口重试开销独立监控。

**监控指标**：
- 接口重试率（次数/总请求）
- 重试耗时占比（重试耗时/总耗时）

- 排队等待时间（任务入队→开始执行）

**测试步骤**：
1. 运行系统 1 小时
2. 采集上述 5 项指标
3. 展示在系统监控面板

**验收标准**：
- 5 项指标全部独立展示 ✓
- 重试率 > 5% 触发预警 ✓
- 降级数据占比 > 10% 触发预警 ✓

## 六、缺陷分类标签

将审核发现的问题映射到拟人化标签，便于快速定位整改方向。

| 缺陷标签 | 对应问题类型 | 典型表现 |
|:---|:---|:---|
| 🩸 **气血堵塞** | 数据流瓶颈 | 链路延迟超标、队列积压、数据库写入阻塞、内存泄漏 |
| 🧠 **神经迟钝** | 感知缺失 | 探针漏报、告警延迟、异常信号未捕获、滑点监控缺失 |
| 🦿 **肢体僵硬** | 调度僵化 | 策略无法热切换、硬编码映射、参数不可动态调整、优化器单一 |
| 💭 **思维卡顿** | 运算瓶颈 | 因子计算超时、AI推理延迟、回测耗时过长、并行能力不足 |
| 🦴 **肌体残缺** | 架构缺陷 | 单点故障、模块缺失、无灾备、权限漏洞、硬编码密钥 |
| 👁️ **意识模糊** | 可视化断层 | 看板数据滞后、错误信息模糊、告警混乱、溯源链路断裂 |
| 🌫️ **感知盲区** | 监控缺失 | 埋点不全、隐性损耗不可见、离线复盘数据缺失、指标口径不一致 |

**使用方式**：审核报告中每个缺陷标注对应标签，如：
> `[🩸气血堵塞] QX-001 未通过：全链路 P99 延迟 = 820ms，超过 500ms 阈值。根因：数据库写入同步阻塞主流程。`
